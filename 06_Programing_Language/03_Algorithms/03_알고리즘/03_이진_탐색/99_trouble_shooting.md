### 개념 학습 정리 - enumerate()의 반환 형태

**문제 상황**: 매개변수 탐색(절단기 높이 문제)에서 나무 높이 합산 시 `for tree_length in enumerate(input_list):`로 작성해 `TypeError: unsupported operand type(s) for -: 'tuple' and 'int'` 발생.

**부족한 개념**: `enumerate()`는 `(인덱스, 값)` 형태의 튜플을 반환하므로, 인덱스가 필요 없는 순회에서는 사용할 필요가 없으며 배열을 직접 순회해야 한다는 개념.

**알게 된 사실**: `for x in list:`는 값만 순회하고, `for i, x in enumerate(list):`는 인덱스와 값을 함께 순회한다. 인덱스가 필요 없는 상황에서 `enumerate()`를 사용하면 값이 아닌 튜플이 변수에 담겨, 이후 연산에서 타입 오류가 발생한다.

**개념이 포함된 섹션**: PL

### 개념 학습 정리 - 매개변수 탐색에서 정확히 일치(==)가 아닌 조건 이상(>=) 탐색

**문제 상황**: "합이 target 이상이 되는 가장 큰 H"를 찾는 문제에서, 반환 조건을 `total_tree_length == t`로 설정함.

**부족한 개념**: 매개변수 탐색은 배열의 특정 값과 정확히 일치하는 지점을 찾는 값 탐색과 다르며, "조건을 만족하는 최댓값/최솟값"을 찾는 문제다. mid가 1씩 변할 때 합계가 나무 개수만큼씩 건너뛰며 변하므로, target과 정확히 일치하는 지점이 존재하지 않을 수 있다는 개념.

**알게 된 사실**: `==` 대신 `>=`(또는 `<=`) 조건으로 "유효한 후보인지"만 판별하고, 유효한 후보를 만날 때마다 별도 변수(`h`)에 저장한 뒤 더 나은 후보가 있는지 계속 탐색해야 한다. 정확한 일치를 요구하는 조건은 매개변수 탐색에서 반복문이 끝내 종료 조건을 만족하지 못해 잘못된 결과(초기값)를 반환하게 만든다.

**개념이 포함된 섹션**: Algorithms

### 개념 학습 정리 - 후보값 갱신 위치와 조건 분기의 범위

**문제 상황**: `h = mid`를 `if`/`else` 두 분기 모두에서 실행하도록 작성해, 마지막에 실행된 분기가 `else`(유효하지 않은 후보)일 경우 `h`가 잘못된 값으로 덮어씌워짐.

**부족한 개념**: 조건 분기에서 특정 변수를 갱신하는 코드가 "조건을 만족했을 때만" 실행되어야 하는지, 아니면 "분기와 무관하게 항상" 실행되어야 하는지를 구분하지 않고 두 분기에 동일한 코드를 배치함.

**알게 된 사실**: 후보값(정답이 될 수 있는 값)은 그 후보가 유효하다고 판별된 조건 분기 안에서만 갱신해야 한다. 조건과 무관한 분기(불만족 시)에 동일한 갱신 코드를 두면, 탐색이 끝나는 시점의 우연한 분기 결과에 따라 값이 덮어씌워지는 오류가 발생한다.

**개념이 포함된 섹션**: PL

### 개념 학습 정리 - 도메인 규칙의 누락(음수 기여분 처리)

**문제 상황**: 나무 길이 합산 시 `total_tree_length += tree_length - mid`로 작성해, 절단 높이(mid)보다 낮은 나무도 음수 값으로 합산에 포함됨.

**부족한 개념**: 문제에 명시된 도메인 규칙("H보다 낮은 나무는 잘리지 않는다")을 코드 로직에 반영하지 못함. 수식만 보고 구현하면 문제의 제약조건이 누락될 수 있다는 개념.

**알게 된 사실**: 절단 높이보다 낮은 나무의 기여분은 0으로 처리해야 하며, `max(0, tree_length - mid)`처럼 음수를 0으로 절삭(clamping)하는 방식으로 구현해야 한다. 수식을 코드로 옮길 때는 수식 자체의 산술적 정확성뿐 아니라, 문제 텍스트에 명시된 예외/경계 규칙이 모두 반영됐는지 별도로 검증해야 한다.

**개념이 포함된 섹션**: Algorithms
