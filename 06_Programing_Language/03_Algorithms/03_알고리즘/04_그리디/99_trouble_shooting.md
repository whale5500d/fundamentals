### 개념 학습 정리 - 튜플 리스트의 타입 힌트 문법

**문제 상황**: 구간 스케줄링 문제에서 함수 시그니처를 `input_list: list[(int, int)]`로 작성함.

**부족한 개념**: 파이썬 타입 힌트에서 튜플을 표기할 때는 `(int, int)`가 아니라 `tuple[int, int]` (3.9 이상) 또는 `Tuple[int, int]`(typing 모듈)를 사용해야 하며, `(int, int)`는 타입 표기가 아닌 튜플 리터럴로 해석된다는 개념.

**알게 된 사실**: 타입 힌트에서 컨테이너 타입(리스트, 튜플, 딕셔너리 등)을 표기할 때는 각 컨테이너 전용 문법(`list[...]`, `tuple[...]`, `dict[...]`)을 따라야 하며, 일반 값 표기(소괄호로 튜플 만들기)와 타입 표기 문법은 서로 다르다.

**개념이 포함된 섹션**: PL

### 개념 학습 정리 - sorted()의 기본 정렬 기준과 key 매개변수

**문제 상황**: 튜플 리스트를 종료 시간 기준으로 정렬하려는 의도로 `sorted(input_list)`만 작성함.

**부족한 개념**: `sorted()`는 `key`를 지정하지 않으면 튜플의 첫 번째 요소부터 순차 비교(사전식 비교, lexicographic comparison)한다는 개념과, 특정 요소만을 비교 기준으로 삼으려면 `key` 매개변수에 값을 추출하는 함수를 전달해야 한다는 개념.

**알게 된 사실**: `sorted(input_list, key=lambda x: x[1])`처럼 `key`에 함수(람다 또는 일반 함수)를 전달하면, 각 원소를 그 함수에 통과시킨 반환값을 기준으로 정렬한다. `lambda 매개변수: 반환값`은 이름 없는 함수를 한 줄로 정의하는 문법이며, `def`로 함수를 따로 선언하지 않고 `key`처럼 함수 자체가 필요한 자리에 간결하게 전달할 때 사용한다.

**개념이 포함된 섹션**: PL

### 개념 학습 정리 - 비트 연산자와 논리 연산자의 혼동

**문제 상황**: 두 조건을 동시에 만족하는지 확인하려는 의도로 `if prev_end < now_start & now_start < cur_fast_start:`를 작성함.

**부족한 개념**: `&`는 비트 연산자(bitwise AND)이고 `and`는 논리 연산자(logical AND)로, 두 연산자는 우선순위와 동작 방식이 다르다는 개념. 불리언(boolean) 조건을 결합할 때는 `and`를 사용해야 한다.

**알게 된 사실**: `&`는 정수의 비트 단위 연산에 사용되는 연산자이며, 불리언 값에 대해서도 동작은 하지만(True/False가 1/0으로 취급됨) 연산자 우선순위가 비교 연산자보다 높아 의도와 다른 순서로 계산될 수 있다. 논리적 조건 결합에는 항상 `and`, `or`를 사용해야 한다.

**개념이 포함된 섹션**: PL

### 개념 학습 정리 - 그리디 비교 기준의 대상 오류(바로 이전 원소 vs 마지막 선택 원소)

**문제 상황**: 구간 스케줄링에서 다음 회의를 선택할지 판단할 때, 비교 기준을 `input_list[i-1][1]`(바로 이전 인덱스의 종료 시간)로 설정함.

**부족한 개념**: 순회 중 일부 원소는 조건을 만족하지 못해 선택되지 않고 건너뛸 수 있으므로, 비교 기준은 "바로 이전 인덱스"가 아니라 "마지막으로 선택이 확정된 원소"여야 한다는 개념. 두 값은 건너뛴 원소가 있을 경우 서로 달라진다.

**알게 된 사실**: 그리디 순차 선택 문제에서는 별도의 상태 변수(예: `last_selected_end`)로 "마지막 확정 선택"을 추적해야 하며, 인덱스 기반의 상대 참조(`i-1`)로는 건너뛴 원소를 반영하지 못해 잘못된 비교가 발생한다.

**개념이 포함된 섹션**: Algorithms
