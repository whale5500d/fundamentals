# 연결 리스트 (linked list)

## 개념

**정의**: 노드 (node)가 값 (data)과 다음 노드를 가리키는 참조 (reference)를 가지고, 참조를 따라 이어진 선형 자료구조다. 배열은 연속된 메모리에 저장되어 인덱스로 접근하지만, 연결 리스트는 노드가 흩어져 있어도 참조로 연결된다. 첫 노드를 가리키는 참조를 `head`라 하고, 마지막 노드의 다음 참조는 `None`이다.

**표 1: 연결 리스트의 종류**
| 종류 | 노드 구성 | 특징 |
|---|---|---|
| 단일 연결 리스트 (singly linked list) | 값, `next` | 한 방향 순회만 가능하다. 코딩테스트 대부분이 이 형태다. |
| 이중 연결 리스트 (doubly linked list) | 값, `prev`, `next` | 양방향 순회가 가능하고, 노드를 알면 O(1)에 삭제할 수 있다. |
| 원형 연결 리스트 (circular linked list) | 마지막 노드의 `next`가 `head` | 순회가 끝나지 않으므로 종료 조건을 별도로 둬야 한다. |

파이썬에는 연결 리스트 내장 타입이 없어서 노드 클래스를 직접 작성한다.

```python
class ListNode:
    def __init__(self, value: int = 0, next_node: "ListNode | None" = None):
        self.value = value
        self.next_node = next_node
```

앞에서 배운 참조 할당(`result = array`)이 노드 연결의 기반이다. `node.next_node = other`는 값을 복사하는 것이 아니라 같은 객체를 가리키게 만든다.

## 핵심 조건

**1. 포인터 재연결 순서**: 연결을 바꾸기 전에 잃을 수 있는 참조를 임시 변수에 저장해야 한다. 순서를 틀리면 뒤쪽 노드 전체에 접근할 방법이 사라진다. 이 구조의 가장 빈번한 오류 지점이다.

**2. 경계 케이스 (edge case)**: 아래 네 가지를 모든 문제에서 확인한다.

- `head`가 `None`인 빈 리스트.
- 노드가 하나뿐인 리스트.
- 삽입 또는 삭제 대상이 `head`인 경우.
- 대상이 마지막 노드인 경우(`next_node`가 `None`).

**3. 더미 노드 (dummy node, sentinel)**: `head` 앞에 값이 없는 임시 노드를 붙이면 `head` 삽입, 삭제의 예외 처리가 사라진다. 반환할 때는 `dummy.next_node`를 반환한다.

**4. 종료 조건**: 순회는 `while node is not None`으로 끝낸다. 사이클이 있는 리스트에서는 `None`을 만나지 못해 무한 루프가 된다. `None` 비교는 `==`가 아니라 `is`를 쓰는 것이 PEP 8의 권장이다.

**5. 연산 비용**: 배열(`list`)과 비교하면 아래와 같다.

**표 2: 배열과 연결 리스트의 연산 비용**
| 연산 | 배열 (`list`) | 단일 연결 리스트 |
|---|---|---|
| 인덱스 접근 | O(1) | O(N) |
| 값 탐색 | O(N) | O(N) |
| 맨 앞 삽입, 삭제 | O(N) | O(1) |
| 맨 뒤 삽입 | O(1) (분할 상환) | O(N), 꼬리 참조 보관 시 O(1) |
| 중간 삽입, 삭제 | O(N) | 위치까지 이동 O(N), 재연결 O(1) |
| 메모리 | 연속, 원소만 저장 | 분산, 노드마다 참조 하나 추가 |

중간 삽입, 삭제의 이점은 "재연결이 O(1)"이라는 것이지, 위치를 찾는 비용까지 줄어드는 것은 아니다. 위치를 이미 알고 있을 때만 배열보다 유리하다.

## 대표 문제 유형

1. 기본 연산: 노드 구현, 앞과 뒤 삽입, 값으로 삭제, 파이썬 `list`와의 변환.
2. 뒤집기 (reversal): 참조의 방향을 반대로 바꾼다. 앞에서 푼 배열 뒤집기는 두 위치의 값을 교환했지만, 연결 리스트는 값이 아니라 참조를 바꾼다.
3. 두 포인터 응용 (fast/slow pointer): 중간 노드 찾기, 사이클 탐지, 뒤에서 K번째 노드. 앞에서 배운 투 포인터가 이동 속도나 간격이라는 새로운 형태로 적용된다.
4. 병합 (merge): 정렬된 두 리스트를 하나로 합친다. 앞에서 정리한 병합 정렬의 병합 단계와 같은 구조다.
5. 복합 응용: 회문 판별 (중간 찾기와 뒤집기 결합), 중복 제거, 두 리스트의 교차점, 리스트 재배치.
6. 이중 연결 리스트 응용: LRU 캐시는 이중 연결 리스트와 해시 테이블을 결합한다.

## 유형 구분 기준

앞에서 배열을 "조작 방식 (operation pattern)"으로 나눴고, 자료구조는 같은 기준이 적용된다. 연결 리스트는 "참조를 어떻게 다시 연결하는가"가 기준이다.

**표 3: 유형 구분 기준**
| 유형 | 핵심 기법 | 우선 확인할 경계 |
|---|---|---|
| 기본 연산 | 임시 변수 또는 더미 노드로 재연결 | 빈 리스트, `head` 삭제 |
| 뒤집기 | `previous`, `current`, `next` 세 변수를 한 칸씩 이동 | 노드 하나, 마지막 `next`를 `None`으로 처리 |
| 두 포인터 | 빠른 포인터는 두 칸, 느린 포인터는 한 칸 이동 | `fast`와 `fast.next` 둘 다 `None` 검사 |
| 병합 | 더미 노드와 꼬리 포인터로 작은 쪽을 이어 붙임 | 한쪽이 먼저 끝났을 때 남은 쪽 연결 |

## 제외 또는 후순위 항목

- 이중 연결 리스트 응용(LRU 캐시)은 해시 테이블(로드맵 4번)이 선행되어야 한다.
- 정렬 문제(연결 리스트 병합 정렬)는 정렬 3종(삽입, 퀵, 계수)이 남아 있어 후순위다.
- 랜덤 포인터가 있는 리스트의 깊은 복사는 해시를 함께 쓰므로 후순위다.

## 입력 형태에 대한 실무 참고

LeetCode 등에서는 연결 리스트가 `ListNode` 객체로 주어진다. 직접 실행해서 검증하려면 파이썬 `list`를 `ListNode`로 변환하는 함수와, 반대로 출력하기 위한 변환 함수를 먼저 만들어야 한다. 첫 문제인 기본 연산에서 이 두 변환 함수를 직접 작성하면 이후 모든 문제에서 재사용할 수 있다.

## 권장 순서

기본 연산 → 뒤집기 → 두 포인터 → 병합. 기본 연산에서 재연결 순서와 더미 노드를 익힌 뒤, 뒤집기에서 세 변수 이동으로 이를 확장한다. 두 포인터는 사이클 탐지에서 종료 조건의 중요성이 드러난다. 병합은 더미 노드가 가장 효과적으로 쓰이는 유형이라 마지막에 둔다.

시작할 유형을 정하면 된다.
