## 프로그래밍 (답안지)

1. 구조화 패러다임(structuring paradigm)
   - 1. ✅ 객체 지향 프로그래밍에 대해 설명하세요.
     - 객체 지향 프로그래밍이란? 이름 그대로 지향하는 프로그래밍의 방향점을 객체로 둔 방식입니다. 기존에는 절차 중심적으로 프로그래밍을 했습니다. 절차적으로 소스 코드를 작성하면 코드가 커질 때 데이터와 함수 간의 결합도가 높아져서, 유지보수가 어려워집니다. 이를 해결하기 위해 데이터와 로직을 하나의 단위로 캡슐화(encapsulation) 개념이 도입되었고, 이후 상속, 다형성 등의 개념이 뒤따라 정립되었습니다. 이런 필요성을 바탕으로 캡슐화된 데이터와 메서드를 하나의 단위인 객체(object)로 묶어서 설계하는 방식을 뜻합니다.
     - 캡슐화란? 데이터와 로직(메서드)를 하나의 단위로 묶는 설계 방식
     - 상속(inheritance)이란? 자식 클래스가 부모 클래스의 속성과 메서드를 물려받아 사용하는 메커니즘으로, 공통 로직을 부모 클래스에 정의하고, 자식 클래스에서 재사용, 확장함으로써 중복 코드를 줄일 수 있습니다.
     - 다형성(polymorphism)이란? 동일한 인터페이스(메서드 이름)가 객체 타입에 따라 서로 다른 동작을 수행하는 특성을 말합니다. 자식 클래스가 부모 클래스의 메서드를 재정의하는 오버라이딩, 동일 이름의 메서드를 매개변수 형태를 다르게 하여 여러 개 정의하는 오버로딩이 대표적인 구현 방식입니다. (overriding, overloading, dynamic binding)
     - 추상화(abstraction)이란? 객체의 복잡한 내부 구현은 숨기고, 외부에서 필요한 핵심 기능(인터페이스)만 노출하는 특성입니다. 사용자는 구현 세부사항을 몰라도 인터페이스만으로 객체를 다룰 수 있습니다. (interface, implementation hiding, essential feature extraction)
   - 3. ✅ 디자인 패턴에 대해 설명해 주세요.
     - 디자인 패턴이란? 소프트웨어 설계 과정에서 반복적으로 발생하는 문제를 검증된 해결 구조로 정형화해둔 코드 패턴입니다. 특정 코드가 아닌 문제, 해결 구조의 템플릿을 제공하며, 목적에 따라 생성 패턴(creational), 구조 패턴(structural), 행위 패턴(behavioral)으로 분류됩니다.
     - 생성 패턴이란? 객체를 직접 생성(new)하는 대신, 생성 로직을 별도 구조로 캡슐화하여 객체 생성 방식을 유연하게 만드는 패턴입니다. 생성 주체와 사용 주체를 분리해 구체 클래스에 대한 의존도를 낮춥니다. 대표적으로 싱글턴(singleton), 팩토리 메서드(factory method), 빌더(builder)가 있습니다.
     - 구조 패턴이란? 클래스와 객체를 조합해 더 큰 구조를 구성하되, 그 결합 관계를 유연하고 단순하게 유지하는 패턴입니다. 서로 다른 인터페이스를 가진 객체를 호환시키거나, 객체 간 관계를 재구성해 확장성을 확보합니다. 대표적으로 어댑터(adapter), 데코레이터(decorator), 퍼사드(facade)가 있습니다.
     - 행위 패턴이란? 객체 간 책임을 어떻게 분배하고 상호작용할지에 초점을 맞춘 패턴이다. 객체 구조 자체보다 객체 간 메시지 교환과 알고리즘의 캡슐화를 다룬다. 대표적으로 전략(strategy), 옵저버(observer), 템플릿 메서드(template method)가 있다.

2. 런타임 자원 관리(runtime resource management)
   - 6. ✅ 동기(Synchronous) 프로그래밍과 비동기(Asynchronous) 프로그래밍의 차이점에 대해 설명해 주세요.
     - 동기, 비동기란? 런타임 작업 순서가 다릅니다. 동기는 순서대로 작업을 실행합니다. 이전 작업이 끝나야 다음 작업이 시작됩니다. 비동기는 작업 완료를 기다리지 않고 다음 코드를 계속 실행합니다. 완료 시점에 콜백이나 이벤트 루프를 통해 결과를 처리하는 방식입니다.
     - 블로킹이란? 함수를 호출한 스레드가 해당 작업이 완료될 때까지 다음 코드로 넘어가지 못하고 대기하는 방식입니다. 호출된 함수가 제어권을 반환하지 않아 호출 스레드가 멈춘 상태가 됩니다.
     - 논블로킹이란? 함수를 호출한 스레드가 작업 완료를 기다리지 않고 즉시 제어권을 돌려받아 다음 코드를 계속 실행하는 방식입니다. 작업 완료 여부는 폴링(polling)으로 확인하거나 콜백(callback)으로 통지받는다.
     - 콜백이란? 특정 작업이 완료된 후 실행되도록 다른 함수의 인자로 전달되는 함수입니다. 호출 시점을 호출자가 아닌 피호출 함수(또는 런타임)가 결정하므로 제어의 역전이 발생합니다.
     - 이벤트 루프란? 콜스택이 비었는지 계속 확인하며, 비어 있으면 태스크 큐에 대기 중인 콜백을 콜스택으로 옮겨 실행시키는 단일 스레드 메커니즘입니다. 비동기 작업(타이머, I/O 등)의 완료 콜백을 순서대로 처리해, 단일 스레드에서도 논블로킹 동작을 가능하게 합니다.

   - 7. ✅ 프로세스와 스레드의 차이점은 무엇이며, 멀티스레딩 환경에서 주의해야 할 점은 무엇인가요?
     - 프로세스란? 운영체제로부터 독립된 메모리 공간(코드, 데이터, 힙, 스택)을 할당받아 실행되는 프로그램의 단위입니다.
     - 스레드란? 하나의 프로세스 내부에서 생성되어 코드, 데이터, 힙 영역은 공유하되 스택만 독립적으로 갖는 실행 흐름의 단위입니다.
     - 메모리 공간 동작 원리? 프로세스는 OS로부터 가상 주소 공간을 할당받아, 영역을 다른 프로세스와 격리된 상태로 유지합니다. 하나의 프로세스에 속한 여러 스레드는 같은 가상 주소 공간 안에서 코드, 데이터, 힙 영역을 공유하고, 스택과 레지스터, 프로그램 카운터만 스레드별로 독립적으로 갖습니다. 이 구조 때문에 스레드 간 컨텍스트 전환이 프로세스 간 전환보다 비용이 낮습니다.
