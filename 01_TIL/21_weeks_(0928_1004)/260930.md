## 네트워크 (답안지)

1. 식별과 이름 해석
   - 2. ✅ URI, URL, URN에 대해 설명해 주세요.
     - URI 문자열을 구성요소로 나누고 각 프로토콜 메시지의 필드로 들어가서 사용됨.
     - URI(Identifier, 식별자): 자원을 식별하는 문자열 전체
     - URL(Location, 위치로 식별): 위치로 식별, 접근 방법을 포함
     - URN(Name, 이름으로 식별): 접근 방법이 없어서 이름을 위치로 바꾸는 별도의 해석이 필요
       - URN의 필요성
     - URL의 구성요소
       - host: DNS 질의의 QNAME
       - port: TCP 헤더의 도착지
       - scheme: 사용할 프로토콜 선택
       - path, query: HTTP 요청 라인
   - 3. ✅ DNS에 대해 설명해 주세요.

2. 전송 규약과 계층 구조
   - 4. ✅ TCP와 UDP 방식의 차이점에 대해 설명해 주세요.
   - 6. ✅ OSI 7계층과 TCP/IP 4계층에 대해 설명하고, 각 계층의 역할을 말해 주세요.
   - 7. ✅ TCP의 3-way handshake와 4-way handshake 과정에 대해 설명해 주세요.

3. 통합 시나리오
   - 9. ✅ 브라우저 주소창에 URL을 입력했을 때 웹 페이지가 표시되기까지의 과정을 설명해 주세요.
     - 전체 과정: URL 파싱, DNS 조회, TCP 연결 수립, TLS handshake, HTTP 요청과 응답, 서버 측 요청 처리, 렌더링, 연결 종료 또는 재사용 순
     1. URL 파싱? URL을 각 과정에서 필요한 구성 요소로 분해하는 과정입니다. scheme, host, port, path, query, fragment 구성요소로 분해합니다.
     2. DNS 조회? (host) 이 중 host의 도메인 이름을 IP 주소로 변환합니다. 브라우저 캐시, OS 캐시, 재귀 리졸버 순으로 확인합니다.
     3. TCP 연결 수립? (port) 3-way handshake, "SYN, SYN+ACK, ACK" 교환으로 양 끝단의 초기 순서 번호(sequence number)를 동기화하고 신뢰성 있는 연결을 만듭니다.
        - 클라이언트 단말의 OS 네트워크 스택과 서버의 OS 네트워크 스택 사이에서 진행됩니다. 브라우저는 직접 패킷을 만들지 않고, OS가 제공하는 socket API의 connect() 호출로 OS에 연결 수립을 요청합니다.
        - 3-way handshake란?
     4. TLS handshake? (scheme) 전송 계층 보안 협상, scheme이 https일 때 사용됩니다. TCP 연결 위에서 암호 스위트(cipher suite)를 협상하고 서버 인증서를 검증합니다.
     5. HTTP 요청과 응답(HTTP request and response)?: (path, query) 클라이언트가 method, path, header로 구성된 요청 메시지를 보내면 서버가 상태 코드(status code)와 본문을 응답합니다.
     6. 서버 측 요청 처리(server-side request handling): 프록시, 로드 밸런서, 웹 서버가 요청을 중계, 분산, 처리합니다.
     7. 렌더링(rendering): (fragment) 응답받은 HTML, CSS를 파싱해 DOM, CSSOM을 만들고 layout(배치)과 paint(그리기)를 수행합니다.
     8. 연결 종료 또는 재사용: 4-way handshake로 연결을 종료하거나, HTTP/1.1의 persistent connection(지속 연결)으로 연결을 재사용합니다.
