## 관계형 데이터베이스 (답안지)

1. 트랜잭션
   - 2. ✅ 트랜잭션에 대해서 설명해 주세요.
     - 트랜잭션이란? 여러 SQL 문을 하나로 묶는 논리적 작업 단위다. 묶인 연산은 모두 반영하거나, 모두 취소한다. 이를 통해 작업 중간에 실패해도 일부만 반영된 상태가 DB에 남지 않는다.
     - 작업 단위란? 업무 관점에서 하나의 완결된 의미를 갖는 연산 묶음이다. 묶음 중 일부만 반영된 상태는 업무적으로 의미가 없으므로 더 쪼갤 수 없는 논리적 단위로 취급한다.
     - 부분 실패란? 하나의 작업 단위를 구성하는 연산 중 일부만 성공하고 나머지는 실패하여, 작업 단위가 완결되지 못한 채 중간 상태가 DB에 남는 현상이다.
     - 부분 실패 발생 원리? 트랜잭션 없이 실행하면 SQL 문 하나하나가 독립된 트랜잭션으로 자동 커밋된다. 먼저 실행된 쿼리문은 커밋되어 DB에 영구 반영되므로, 이후 문에서 실패해도 앞선 결과를 되돌릴 방법이 없다.
       - 발생 조건 3가지
         - 하나의 작업 단위가 2개 이상의 SQL 문으로 구성
         - 각 SQL 문이 개별적으로 커밋
         - SQL 문 사이에서 실패가 발생한다.
     - 커밋이란? 트랜잭션의 변경 사항을 DB에 영구 반영하고 트랜잭션을 종료하는 명령이다. SQL에서는 COMMIT으로 실행한다.
   - 3. ✅ ACID에 대해서 설명해 주세요.
     - ACID란? 트랜잭션이 정합성(integrity)을 보장하기 위해 만족해야 하는 4가지 특성이다. 부분 실패(partial failure)는 원자성으로, 커밋 후 장애에도 결과가 유지되는 성질은 지속성으로 보장한다.
       - ACID 4가지 특성
         - 원자성: 트랜잭션의 연산은 전부 반영되거나 전부 취소된다.
         - 일관성: 트랜잭션 전후에 DB가 정의된 제약 조건(constraint)을 만족하는 유효 상태를 유지한다.
         - 격리성: 동시에 실행되는 트랜잭션이 서로의 중간 결과에 간섭하지 않는다.
         - 지속성: 커밋된 결과는 장애가 발생해도 유지된다.
   - 4. ✅ 트랜잭션의 격리수준에 대해서 설명해 주세요.
   - 9. ✅ 데이터베이스에서 데드락이 발생하는 이유와 대응 방법을 설명해 주세요.

2. 스키마 설계
   - 7. ✅ 데이터베이스 정규화가 필요한 이유와 반정규화를 고려하는 경우를 설명해 주세요.
     - 정규화란? 함수적 종속성을 기준으로 DB 테이블을 분해해 데이터 중복을 최소화하는 데이터베이스 설계 과정입니다. 이를 통해 삽입, 갱신, 삭제 이상 현상을 방지할 수 있습니다.
     - 반정규화란? 정규화된 스키마에 의도적으로 중복을 허용하여 조회 성능을 높이는 재설계 과정입니다. JOIN 비용을 줄일 수 있으나, 중복 데이터의 정합성 관리 비용이 증가합니다.
     - 함수적 종속성: 하나의 속성이 정해지면 다른 속성이 정해지는 관계
       - 삽입 이상: 과목코드가 비어 저장 불가
       - 갱신 이상: 2행을 모두 수정해야 하며, 1행만 수정하면 학과가 2개로 불일치
       - 삭제 이행: 정보도 함께 삭제
     - Trade-off (상충 관계) 정리
       - 정규화를 하면 정합성이 높아짐. 대신 JOIN 비용도 함께 증가
       - 반정규화를 하면 조회가 빠름. 중복 데이터의 정합성 관리가 필요
     - 정규화로 JOIN 횟수가 증가하는 원리: 분해 전에 한 행에 있던 정보를 조회하기 위해 외래키 = 기본키 조건으로 테이블을 다시 결합(JOIN)에야 한다. 테이블 N개의 정보를 한 결과가 조회하려면 JOIN이 N-1회 필요하다.
