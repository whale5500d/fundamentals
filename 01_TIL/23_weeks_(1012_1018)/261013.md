## 운영체제 1 (답안지)

1. 실행 단위
   - 10. ✅ 프로세스와 스레드 차이에 관해 설명해 주세요.

2. 메모리 관리
   - 4. ✅ 가상메모리가 무엇인가요?
     - 가상메모리란? virtual memory (가상메모리)는 운영체제가 각 process (프로세스)에 물리 memory (메모리) 크기와 배치에 독립적인, 연속적이고 사적인 주소 공간(virtual address space, 가상 주소 공간)을 제공하고, 가상 주소를 물리 주소로 변환하는 기법이다. 물리 메모리가 부족하면 일부 페이지를 storage (저장장치)의 swap (스왑 영역)에 보관하여, 물리 메모리보다 큰 주소 공간을 사용할 수 있게 한다.
   - 7. ✅ 스택 영역과 힙 영역의 차이점은 무엇입니까?

3. CPU 시간 배분
   - 6. ✅ CPU 스케줄링(Scheduling)이란 무엇입니까?

4. 동기화와 동시성 문제
   - 3. ✅ 뮤텍스란 무엇입니까?

5. 전체
   - 1. ✅ 운영체제에 대해 설명해주세요.
     - 운영체제? 하드웨어 자원을 관리하고, 응용 프로그램이 안전하고 편리하게 하드웨어 자원을 사용하도록 추상화된 인터페이스를 제공하는 시스템 소프트웨어이다. 핵심 구성 요소는 커널이며, 응용 프로그램은 시스템 콜을 통해 커널 기능을 사용한다.
     - 하드웨어 자원 관리? CPU, Memory, Storage, I/O 관리를 의미함. 여러 실행 단위에 배분하고 회수함.
     - 추상화된 인터페이스? 복잡한 하드웨어를 process, 가상 주소 공간, file 등 단순한 개념으로 제공함.
     - protection(보호)? 실행 단위 간 메모리와 자원 접근을 격리하여 서로의 오동작이 전파되지 않게 함.
     - kernel(커널)? 운영체제에서 특권 모드(privileged mode)로 동작하며 하드웨어를 직접 제어함.
     - system call(시스템 콜)? 응용 프로그램이 커널 기능을 요청하는 유일한 공식 경로.
     - 추상화된 인터페이스 하나를 사례로 들어, 운영체제의 동작 원리를 커널과 시스템 콜 기준으로 설명하고, 해당 인터페이스가 관리하는 하드웨어 자원과 그 결과로 보장되는 보호를 설명하라.
       1. 사례 1 (file)
          - (사례 선정) file은 storage(저장장치, 디스크)라는 하드웨어를 '이름이 있는 바이트 배열'로 추상화한 인터페이스입니다. 응용 프로그램은 디스크의 블록 번호, 컨트롤러 명령을 알지 못하고 file descriptor(파일 디스크립터, 정수 핸들)만 사용합니다.
          - (동작 원리) 응용 프로그램이 cat data.txt를 실행하여 파일을 읽는 경우
            1. 응용 프로그램(user mode, 사용자 모드): 파일을 열기 위해 파일 열기 system call(open)을 호출
            2. CPU: trap(트랩, 소프트웨어 인터럽트) 명령으로 user mode에서 kernel mode(커널 모드, 특권 모드)로 전환
            3. 커널: 경로 이름을 해석하고, 호출한 process(프로세스)의 접근 권한을 검사
            4. 커널: 검사를 통과하면 process별 file descriptor table (파일 디스크립터 테이블)에 항목을 추가하고 정수 값(예: 3)을 반환
            5. 응용 프로그램: 파일 읽기 system call (read)을 file descriptor 3으로 호출
            6. 커널: file descriptor를 내부 파일 객체로 변환하고, 필요 시 device driver (디바이스 드라이버)를 통해 디스크에 읽기를 요청
            7. 커널: 읽은 데이터를 사용자 영역 buffer (버퍼)로 복사하고, user mode로 복귀
          - (결과로 발생하는 보호) 하드웨어 직접 접근 차단, 접근 권한 검사, process 간 격리, 커널 메모리 보호
       2. 사례 2 (가상 주소 공간)
          - (사례 선정) virtual address space는 물리 memory (메모리, RAM)를 “process (프로세스)마다 독립적이고 연속적인 주소 범위”로 추상화한 인터페이스이다. 응용 프로그램은 물리 주소와 다른 process의 메모리 배치를 알지 못하고, 자신의 가상 주소만 사용한다. 가상 주소와 물리 주소의 변환은 kernel이 관리하는 page table(페이지 테이블)과 MMU(Memory Management Unit, 주소 변환 하드웨어)가 담당한다.
          - (동작 원리) C 프로그램이 malloc(1MB)로 메모리를 요청하고, 할당된 영역에 처음 값을 쓰는 경우이다. glibc의 malloc은 요청 크기가 기본 임계값(128KB) 이상이면 mmap system call을 사용하고, 그보다 작으면 주로 brk를 사용한다. 이 사례의 1MB는 mmap 경로이다.
            1. 응용 프로그램 (user mode, 사용자 모드): malloc(1MB)를 호출함. glibc가 내부적으로 메모리 매핑 system call (mmap)을 호출함.
            2. CPU: trap (트랩, 소프트웨어 인터럽트)으로 user mode에서 kernel mode (커널 모드, 특권 모드)로 전환함.
            3. 커널: 호출한 process의 주소 공간에서 비어 있는 가상 주소 범위를 찾아 VMA (Virtual Memory Area, 가상 메모리 영역)로 등록함. 이때 권한(읽기/쓰기)도 기록함.
            4. 커널: 시작 가상 주소를 반환하고 user mode로 복귀함. 이 시점에는 물리 메모리를 할당하지 않음 (lazy allocation, 지연 할당).
            5. 응용 프로그램: 반환된 주소에 처음 값을 씀.
            6. MMU, CPU: page table에 해당 페이지의 매핑이 없어 page fault (페이지 폴트, 변환 실패 예외)를 발생시키고 kernel mode로 진입함.
            7. 커널: 접근 주소가 5단계의 VMA 범위 안이고 권한이 맞는지 검사함. 통과하면 빈 물리 frame (프레임, 물리 메모리의 페이지 크기 단위)을 0으로 채워 할당하고, page table에 가상 페이지와 물리 frame의 매핑을 기록함.
            8. CPU: 중단된 쓰기 명령을 재실행함. 이후 같은 페이지 접근은 MMU가 page table(및 TLB, 변환 캐시)로 변환하며 커널 개입이 없음.
          - (결과로 발생하는 보호) process 간 메모리 격리, 페이지 단위 접근 권한 검사, 매핑이 없는 주소 접근 차단, 커널 메모리 보호, 물리 메모리 총량 보호
     - 무엇이 실행되는가?
     - 자원을 어떻게 배분하는가?
     - 공유 시 무엇이 깨지는가?
