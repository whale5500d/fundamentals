## 운영체제 2 (답안지)

1. 실행 단위의 구조
   - 3. ✅ 프로세스 제어 블록(PCB)이란 무엇입니까?
     - 프로세스: 실행 중인 프로그램의 인스턴스, 주소 공간, 레지스터, 열린 파일 등 실행에 필요한 자원의 묶음
     - 프로세스 상태의 종류: 생성, 준비, 실행, 대기, 종료
     - 프로그램 카운터: 프로세스가 다음에 실행할 명령어의 주소
     - PCB: 운영체제 커널이 프로세스 하나당 하나씩 유지하는 자료구조. 프로세스를 관리하는 데 필요한 정보를 모두 저장한다.
       - 프로세스 관리에 필요한 정보: 프로세스의 식별자, 상태, 프로그램 카운터, CPU 레지스터, 스케줄링 정보, 메모리 관리 정보, 입출력 상태 정보를 저장한다.
       - 문맥 교환 시 커널은 현재 프로세스의 실행 상태를 PCB에 저장하고 다음 프로세스의 PCB에서 상태를 복원한다. 커널이 프로세스 중단 후 같은 지점에서 재개할 수 있도록 PCB가 도움.
   - 1. ✅ 싱글 스레드와 멀티 스레드의 장단점에 대해서 설명해주세요.
     - CPU 스케줄링: 운영체제 커널의 스케줄러(scheduler)가 프로세스 중 다음 CPU를 할당할 대상을 선택하는 동작
     - 스레드: 프로세스 내부의 실행 흐름 단위, CPU 스케줄링의 기본 단위
       - 싱글 스레드는 프로세스당 실행 흐름이 하나여서 구조가 단순하고 동기화 문제가 없지만, 블로킹 발생 시 프로세스 전체가 멈추고 멀티 코어를 활용할 수 없다.
       - 멀티 스레드는 프로세스당 실행 흐름이 여럿이며 주소 공간(code, data, heap)을 공유하므로 응답성과 자원 효율, 멀티 코어 활용 측면이 유리하다. 하지만 공유 자원 접근에 대한 동기화가 필요하고 스레드 하나의 오류가 프로세스 전체에 영향을 줄 수 있다.
     - 공유 자원: 스레드가 공유하는 자원, code, data, heap 영역과 열린 파일 목록
     - 고유 자원: 스레드마다 독립적으로 갖는 자원, stack, register, PC, PCB 저장되는 실행 상태
     - 병행성, 병렬성
     - 경쟁 상태, 교착 상태 연결해서 설명해보면 좋을 듯

2. 실행 단위의 상태와 전환
   - 2. ✅ 프로세스의 상태와 상태 전이에 대해 설명해주세요.
   - 4. ✅ 문맥 교환(Context Switching)이란 무엇이며, 어떤 비용이 발생하나요?
     - 문맥: 프로세스를 중단했다가 같은 지점에서 재개하는 데 필요한 실행 상태. PC, CPU 레지스터 값, 메모리 관리 정보가 포함.
     - 스케줄러: 앞서 배운 CPU 스케줄링에서 다음 실행 대상을 결정하는 커널 구성 요소.
     - 디스패처: 스케줄러가 선택한 대상으로 CPU 제어권을 넘기는 커널 구성 요소.
     - 문맥 교환: 실행 중인 프로세스의 문맥을 PCB에 저장하고, 다음 프로세스의 문맥을 PCB에서 복원하여 CPU를 넘기는 동작이다. 비용은 레지스터 저장/복원, 스케줄러 실행에 드는 직접 비용, 그리고 TLB, CPU 캐시 내용이 무효화되어 교환 직후 miss가 늘어나는 간접 비용으로 나뉘며, 교환 중에는 사용자 작업이 진행되지 않으므로 교환이 잦을수록 처리량(throughtput)이 감소한다.
