# 4. (사례 3) 개인 비서 챗봇

## 도입

- 주어진 입력값을 기반으로 실제 사람이 작성한 듯한 글을 생성한다.
- 출시된 지 3개월 이내에 1억 명 이상의 사용자를 확보했다.
- 빠른 성장은 생성형 AI의 능력뿐만 아니라, 일상적인 과제 해결 및 생산성 향상 측면의 잠재력을 보여준다.

## 머신러닝 관점으로 문제 정의하기

### 시스템의 입력과 출력 구체화하기

- 입력: 사용자가 제공하는 텍스트 프롬프트(질문, 명령 또는 다른 형태의 텍스트)
- 출력: 맥락상 적절하고 관련성이 높은 답변

### 적절한 머신러닝 방법 선택하기

- 선택지: 인코더, 디코더, 인코더-디코더
- 선택: 디코더 전용 트렌스포머
- 근거: 반복적으로 입력 시퀀스를 처리하고 새로운 시퀀스를 생성하기 때문에 생성형 작업에 널리 사용된다. 대표적으로 텍스트 생성 작업으로, 이전 단계에서 생성된 토큰을 기반으로 한 번에 토큰 하나씩 시퀀스를 생성한다.

  - 민감 정보 익명화
  - 저품질 데이터 제거
  - 중복 데이터 제거
  - 관련 없는 데이터 제거
  - 텍스트 토큰화

## 모델 개발

### 구조

- 디코더 전용 트랜스포머
- 텍스트 임베딩, 트랜스포머 블록, 예측 헤드는 2장과 유사하지만,
- 훨씬 더 개선된 방식의 위치 인코딩을 사용한다.

- "Attention is All You Need" 이라는 논문에서 소개한 트랜스포머 구조는 시퀀스를 다루도록 설계되었다. 그래서 텍스트를 이해하고 각 단어 간 관계 파악이 필요한 작업에 효과적이다.
- 트랜스포머에는 세 가지의 주요 변형이 존재한다. 그 중 디코더 전용 트랜스포머는 반복적으로 입력 시퀀스를 처리하고 새로운 시퀀스를 생성한다.

- 위치 인코딩: 챗봇의 입력 시퀀스는 단일 문장 또는 이메일보다 훨씬 더 길다. 모델이 모든 토큰의 위치와 그들 간의 관계를 이해할 수 있도록 하는 위치 인코딩 방법이 필요하다.
- 유명한 LLM에서 사용하는 강력한 위치 인코딩 기법인 RoPE(회전 위치 임베딩)에 대해 깊이 있게 알아볼 예정이다. (절대 -> 상대 -> RoPE 순)

0. 위치 인코딩(p.62): 위치 인코딩으로 트랜스포머에 입력 시퀀스 내에서 각 토큰의 위치 정보를 제공한다. 등장 배경은 '트랜스포머가 내부적으로 입력 토큰의 순서를 고려하지 않는다'는 점에서 출발한다. 순열의 영향을 받지 않기 떄문에 어텐션 메커니즘이 시퀀스 내 토큰 위치를 고려하지 않는다는 점을 알 수 있다. 위치 인코딩은 일반적으로 고정 위치 인코딩, 학습 위치 인코딩 두 가지 방법으로 이루어진다.
1. 절대 위치 인코딩: 시퀀스 내 각 토큰의 위치를 고유한 벡터로 표현하는 방법. 토큰 간 상대적 거리 정보나 다양한 길이릐 시퀀스 또는 새로운 토큰의 위치에서 일반적인 성능을 나타내기 힘들다.
2. 상대 위치 인코딩: 두 토큰 간 위치의 차이를 인코딩하는 방법. (T5, DeBERTa) 어텐션 메커니즘의 q_m, k_m의 점곱이 더 이상 간단한 점곱으로 표현될 수 없기 때문에 복잡성이 커진다. 이는 선형 어텐션과 같은 효율적인 기법을 사용할 수 없게 만든다는 한계가 있다.
3. 회전 위치 인코딩(RoPE): 토큰 임베딩에 적용한 회전 행렬로 위치 정보를 표현한다. 추가적인 수학적 연산이 필요하다. (몹시 복잡하진 않다.)

- RoPE의 장단점
  - 장점
    - 변환 불변성
    - 상대적 위치 표현
    - 배운 적 없는 위치에 대한 일반화
  - 단점
    - 수학적 복잡도

### 학습

- 언어 모델을 학습하기 위헤서는 2단계 전략을 수행한다.
  1. 비지도 사전 학습(unsupervised pretraining)
  2. 지도 미세 조정(supervised finetuning)
- 챗봇을 고도화하기에 충분치 않다.
- ChatGPT를 포함한 대부분 챗봇은 세 단계의 학습 전략을 사용한다.
  1. 사전 학습(pretraining)
  2. 지도 미세 조정(supervised finetuning)
  3. RLHF(Reinforcement Learning from Human Feedback, 사람의 피드백을 기반으로 한 강화 학습)

1. 사전 학습
   - (소스) 인터넷에서 가져온 대규모 텍스트 데이터로 학습
     - Common Crawl, C4, GitHub, Wikipedia, Books, ArXiv, Stack Exchange
   - (목표) 세계 지식에 대한 폭넓은 이해력을 가진 모델의 기본 형태 구현
     - 디코더 전용 트랜스포머를 학습할 것이므로, 머신러닝의 목표는 다음 토큰 예측이다. 손실 함수로는 예측한 토큰의 확률과 정답 토큰의 차이를 측정할 수 있는 교차 엔트로피를 사용한다.
   - (기타) 상당한 연산 자원 요구. 수천 대의 GPU, 수백만 달러의 비용, 수개월의 학습 시간 필요
   - (결과) 언어를 이해하는 모델을 만들 수 있다. 다만, 텍스트 프롬프트에 이어질 말을 만드는 정도만 가능하다. 질문에도 잘 대답하는 유용한 챗봇을 만들려면 기본 모델을 더 학습시키기 위한 지도 미세 조정이 필요하다.

2. 지도 미세 조정
   - (소스) 프롬프트, 응답 형식으로 구성된 더 작은 규모의 고품질 데이터 세트
     - demonstration data(시범 데이터: (프롬프트, 응답) 형식으로 구성한 학습 데이터)
     - InstructGPT, Alpaca, Dolly-15k, FLAN 2022
     - 사전 학습 데이터와의 차이: 규모와 품질. 규모가 훨씬 작고, 품질이 우수하다. 헬스케어 및 금융 등 특화된 산업 분야에선 데이터의 정확성과 관련성을 확보하기 위해 전문가를 고용하여 작업한다.
   - (목표) 기본 모델의 갖고 있는 언어에 대한 이해력과 보편적인 지식을 유지하면서, 프롬프트에 대해 단순히 이어 말하는 게 아니라 응답할 수 있도록 적응시키는 것이다.
     - 마찬가지로 다음 토큰 예측이다. 손실 함수는 교차 엔트로피로 유지한다.
   - (결과) 단순히 텍스트 프롬프트에 말을 잇는 것이 아니라 구체적이고 도움되는 응답을 생성한다. 대개 문법적 오류가 없고 합리적인 응답을 생성한다. 항상 최상의 답변을 만들어 내지는 못할 수도 있고, 위험한 답변일 수도 있다. 안전하고 도움되는 응답을 만들기 위해 RLHF로 추가적인 미세 조정이 필요하다.

3. RLHF
   - 사람의 선호에 맞추는 정렬 단계로, 선호하는 응답을 생성하도록 적응시키는 것을 의미한다.
   - 모델의 응답과 프롬프트의 관련성을 평가할 수 있는 독립적인 보상 시스템으로, 높은 점수를 받는 응답을 생성하는 것이 핵심 개념이다.
   - RLHF는 보상 모델 학습, 지도 미세 조정 모델 최적화 두 단계로 구성된다.
     1. 보상 모델 학습: 프롬프트와 응답의 관련성을 평가하는 보상 모델을 학습하는 방법이다. (프롬프트, 응답) 쌍을 입력으로 받아서 응답의 유용성을 예측한 점수를 출력한다. 점수가 높을수록 응답이 유용하다고 예상할 수 있다.
        - (소스) 수동으로 프롬프트 수집 및 목록화, 지도 미세 조정 모델로 여러 응답 생성, 응답 순위 매기기, 선호 쌍 만들기 순으로 학습 데이터 구성
        - (구조) 지도 미세 조정 모델을 복사한 후 (프롬프트, 응답) 쌍에 대해 관련성 점수를 출력하는 예측 헤드를 추가하는 것이다.
        - (목표) 선호 쌍(프롬프트, 승리 응답, 패배 응답)이 주어졌을 때, 승리와 패배 점수 차를 최대화하는 것이다. 점수 차가 너무 작은 경우 모델에 패널티를 부여하는 손실 함수가 필요하다. 흔히 사용하는 손실 함수는 마진 순위 손실(margin ranking loss)이다.
        - (결과) (프롬프트, 응답) 쌍에 대한 관련성 점수를 예측하는 보상 모델이다.
     2. 지도 미세 조정 모델 최적화: 보상 모델의 도움을 받아 지도 미세 조정 모델을 최적화한다.
        - (소스) 대개 작업자가 만든 프롬프트로 구성되어 있으며, 개수는 만 개에서 10만 개 사이이다.
        - (방식) PPO(Proximal Policy Optimization, 근접 정책 최적화)와 같은 강화 학습 알고리즘을 흔히 사용한다. 이를 통해 지도 미세 조정 모델은 보상 모델이 에측하는 점수를 최대화하도록 미세 조정된다.
        - (목표) 보상 모델의 점수에 근거해 지도 미세 조정 모델이 유용한 응답을 생성하는 것이다. PPO, DPO(Direct Policy Optimization, 직접 정책 최적화) 등의 강화 학습 알고리즘을 사용한다. 이러한 알고리즘에 대한 상세한 설명은 머신러닝 시스템 설계 면접의 범위 밖이다.
        - (결과) 챗봇으로 활용할 수 있는 최종 모델이다. 현재 가장 널리 사용되는 프론티어 LLM 모델이다.

### 샘플링

- (목적, p.75) 학습 데이터에 내재된 데이터 분포를 따라가도록 학습한다. 학습이 끝나면 학습 데이터와 유사한 새로운 샘플을 생성할 수 있다. 샘플링이란 학습한 생성형 모델로 새로운 데이터를 생성하는 과정을 말한다.
- (목적, p.146) 모델이 예측한 확률 분포에서 토큰을 선택하는 방식을 의미하며, 일관되고 유용한 응답의 생성을 목표로 한다.
- 텍스트 생성 방법은 다양하다. 어떤 방법은 결정적이고, 어떤 방법은 확률적이다. 어떤 방법이 자유 응답형의 텍스트 생성에 적합한지 살펴볼 것이다.
  1. 결정적 방법: 텍스트 길이가 짧고 규칙적인 경우 잘 동작한다. 대화와 같이 출력의 길이가 다양하고 자유로운 형식의 텍스트 생성에는 효과적이지 않다.
     - 탐욕 검색의 한계: 매 단계마다 가장 높은 확률의 토큰을 선택하는 방법으로, 반복과 비최적화 생성 문제가 있다. 반복은 "탐욕 검색 방식을 사용했을 때 텍스트가 금방 반복되는 것"을 말한다. 모델이 동일한 토큰 시퀀스를 사용하게 되면서 루프에 갇힐 때가 있다. 비최적화 생성은 탐욕 검색이 대안을 고르지 않는다는 것을 말한다. 이로 인해 낮은 확률의 토큰 뒤에 숨겨진 높은 확률의 토큰 시퀀스를 놓칠 수 있다.
     - 빔 검색의 한계: 상위 k개의 시퀀스를 동시에 추적하는 방법으로, 비효율성과 반복 문제가 있다. 비효율성은 "여러 개의 시퀀스를 한 번에 평가해야 하므로 연산이 비효율적일 수 있고 생성 과정이 느리다"는 점을 말한다. 반복은 "반복적이고 포괄적인 답변 생성"을 말한다. 때떄로 루프에 갇히거나 같은 문구를 반복하기도 한다.
  2. 확률적 방법: 무작위성을 활용해 텍스트를 생성한다. 정해진 답이 없는 생성 작업에 적합하다. 대표적으로 다항 샘플링, Top-k 샘플링, Top-p 샘플링(핵 샘플링)으로 3가지다.
     - 다항 샘플링: 모델이 예측한 확률 분포에 근거하여 다음 토큰을 선택한다. 각 토큰에 해당하는 확률 값이 있고, 이를 기반으로 토큰을 선택한다. 출력의 다양성은 보장하지만, 무작위성의 수준이 상당하며 확률 분포가 균등할 경우 더욱 심하다. 일관성이 없는 생성 결과를 내놓는다. 따라서 LLM이 텍스트를 생성할 때 다항 샘플링은 잘 사용하지 않는다.
     - Top-k 샘플링: 전체 확률 분포에서 샘플링 대신 가장 확률이 높은 k개의 토큰 중에서 선택한다. 일관성과 다양성 사이의 균형을 맞출 수 있다. 어느 정도의 무작위성은 허용하면서 관련없는 토큰이 선택될 가능성은 줄인다. (GPT-2가 초기에 Top-k 샘플링을 사용한 것은 모델이 성공과 인기를 얻는 데에 중요한 역할을 했다.) 다만, 항상 고정된 숫자의 토큰으로부터 샘플링하기에 예측된 확률 분포가 급격한 분포일 경우, 모델이 최고의 선택지를 놓쳐 비논리적인 결과를 만들 수 있고, 평평한 분포일 경우, 단어의 선택지를 충분히 고려할 수 없으므로 모델의 창의성에 제약이 생긴다.
     - Top-p 샘플링: 후보 토큰의 합산된 확률 값을 기반으로, 샘플링 후보 토큰의 개수를 그때마다 조정하는 방법이다. 가장 높은 k개 토큰에서 샘플링하지 않고 누적 확률 값이 0를 초과하는 가장 작은 토큰 집합으로 샘플링한다. 무작위성을 어느 정도 포함하면서도 가장 그럴듯한 토큰에 집중하기 때문에 텍스트가 일관되고 문맥적 관련성이 높다.
     - 다양한 샘플링 방법마다 더 많은 세부적인 내용이 존재한다. 최신 샘플링 방법에서 활용되는 유명한 기법 두 가지는 온도, 반복 패널티이다.

## 평가

### 오프라인 평가 지표

- LLM을 평가하기 위해서는 여러 평가 지표가 필요하다. 복잡한 방식으로 동작하며 작업 유형에 따라 수행 내용이 달라진다. 따라서 모델이 효과적이고 안전하게 동작하는지 확인하기 위해서는 다양한 과제를 통해 역량을 평가해야 한다.

1. 전통적인 평가: 성능에 대한 지표로 Perplexity가 대표적이다. 모델이 텍스트 형태의 토큰 시퀀스를 얼마나 정확하게 예측하는지 측정한다. Perplexity 값이 낮을수록 모델이 텍스트에 포함된 토큰에 높은 확률을 부여하고 있다는 의미다.
2. 과제별 평가: 다양한 과제를 통해 효과적으로 모델의 성능을 평가할 수 있다. 종합적인 접근은 강/약점을 파악하기에 도움이 된다. (상식 추론, 일반 상식, 독해력, 수학적 추론, 코드 생성, 종합 벤치마크)
   - 상식 추론 벤치마크: PIQA(Physical Interaction QA), SIQA, HellaSwag, WinoGrande, OpenBookQA, CommonsenseQA (각 벤치마크별로 서로 다른 측면에 초점이 맞춰져 있다.)
   - 일반 상식 벤치마크: TriviaQA, Natural Question(NQ), SQuAD
   - 독해력 벤치마크: SQuAD, QuAC, BoolQ
   - 수학적 추론 벤치마크: MATH, GSM8K
   - 코드 생성 벤치마크: HumanEval, MBPP(MultiPL-E Benchmarks for Programming Problems)
   - 종합 벤치마크: MMLU, MMMU, AGIEval, Meta Llama 3 human evaluation
3. 안전성 평가
   - 위험성 및 유해 콘텐츠: RealToxicityPrompts(PerspectiveAPI), ToxiGen, HateCheck
   - 편향 및 공정성: CrowS-Pairs(성별, 종교, 인종/피부색, 성적 지향성, 나이, 국적, 장애, 외모, 사회경제적 지위), BBQ, BOLD
   - 진실성: TruthfulQA
   - 사용자 프라이버시 및 데이터 유출: PrivacyQA
   - 적대적 공격에 대한 강건성: AdvGLUE, TextFooler, AdvBench
4. 사람의 평가: 놓칠 수 있는 세부적인 측면과 예상하기 어려운 다양한 측면을 평가할 수 있다.

### 온라인 평가 지표

- 실제 배포 단게에서 얼마나 잘 동작하는지 측정하는 과정이다. 다음과 같은 지표를 사용한다.

1. 사용자의 피드백과 별점
   - 응답에 대한 직접적인 만족도 평가 가능, 개선이 필요한 부분 쉽게 파악
2. 사용자 참여도
   - 만들어진 쿼리의 개수, 세션 지속 기간 등의 지표는 사용자 참여도를 측정할 수 있는 중요한 신호임.
   - 참여도가 높으면 대개 LLM이 유용한 정보를 효과적으로 제공하고 있음을 나타낸다.
3. 전환율
   - 실사용자 중 서비스를 구매하거나 구독한 사용자의 비율. 전환율은 매우 중요한 지표임.
   - 높은 전환율은 사용자가 서비스에 비용을 지불할 만큼 LLM이 우용함을 나타내기 때문임.
4. 실시간 순위
   - 다양한 LLM의 성능을 실시간으로 추적하여 반영하는 순위표임. 대표적으로 "LMSYS 챗봇 아레나".
   - LLM을 평가하기 위해 만들어진 사용자 참여형 개방 플랫폼으로, 80만 개 이상의 비교 쌍을 근거로 모델을 평가하여 순위를 매긴다.
